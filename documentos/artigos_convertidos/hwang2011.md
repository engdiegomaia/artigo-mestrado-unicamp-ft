I NTRODUCTION HYPERSPECTRAL imaging has been widely used in remote sensing for the purposes such as resource management, agriculture, mineral exploration, and environmental mon-itoring. It uses an array of sensors to collect a set of imagesacross the spectrum. Each image corresponds to a speciﬁc spectral band. These images form a three-dimensional data cube for further processing and analysis. The data volume of hyperspec-tral images is huge. For example, a scene data cube recorded bythe NASA JPL airborne visible/infrared imaging spectrometer (A VIRIS) [1] contains 224 bands of 512 614 sized images. Excessive data volume not only requires a large data deposi-tory system, but also requires a wider data transmission band-width between the satellite and the ground station. To mitigate the problem, state of the art data compression techniques are applied. Existing compression schemes such as JPEG are lossyand not efﬁcient for the hyperspectral images because they failto fully exploit the spectral data correlation. Besides the algorithmic aspect, an efﬁcient system implementation to support on-board processing, which alleviates the downlink bandwidth requirement, is crucial. Early attempt such as [2] adopted a discrete wavelet transform (DWT) plus set parti-tioning in hierarchical trees (SPIHT) coding routine as the com-pression algorithm. The design was a stand-alone module and implemented in three ﬁeld-programmable gate arrays (FPGAs). In [3], a compression algorithm developed by NASA was im-plemented in a Xilinx FPGA platform equipped with an em-bedded PowerPC core. In [4], the compression algorithm was designed as a reconﬁgurable computing core and implemented in an FPGA with system-on-chip (SoC) platform support. In[5], a “fast lossless” (FL) compression algorithm was imple-mented using FPGA. Due to the employment of a simple entropy coder facilitating a fully hardwired design, acceleration of 33 times faster than the software implementation was reported.In this letter, the emphasis will be on how to achieve a systemimplementation via hardware/software (HW/SW) codesign and on how to optimize the individual designs and minimize the HW/SW communication overhead. The organization of this letter is as follows. In Section II, the overall compression scheme is described. In Section III, the implementation details of the compression scheme on an embedded platform are elaborated. These include the how theHW/SW partitioning was achieved via system proﬁling and how the respective hardware and software designs were developed and optimized. The major contribution of this letter is that a sys-tematic approach for system mapping and various optimizationefforts to obtain the best performance under the constraints of the target platform are thoroughly developed. This would far exceed the available bus bandwidth(two pixels at a time) if one prediction is achieved per clock cycle at a 33 MHz working frequency. To bridge the gap of data access bandwidths between the bus and the computingkernel, a hierarchical memory access scheme was developed.The memory hierarchy, as shown in Fig. 6, starting with a SD card to store the entire set of hyperspectral images, followed by an off-chip SDRAM memory module as the frame buffer,eight on-chip line buffers to hold active line data, and two setsof shift registers to store the context window information. An AHB bus wrapper is included to support the AHB bus protocol. Two out of the eight line buffers constantly fetch off-chip data from SDRAM via the AHB bus wrapper. The fetchedin data along with data from the remaining six line buffers are fed to the two sets of shift registers. The external memory access is performed in a line by line basis. The peak FPGA off-chip dataaccess is conﬁned to 16b 2 33 MHz. The two sets of shift registers, however, provide a data bandwidth up to 10.56 Gb/s. The implementation of multi-LUT scheme utilizes on-chip SRAM modules generated by the Xilinx core-generator. EachLUT operation requires two data accesses, one for read and onefor write (LUT update). To achieve this in one clock cycle needs a dual-port memory conﬁguration. Due to limited resources of block RAMs, a single-port memory conﬁguration was chosenand the prediction throughput was reduced to 16.5 M pixels persecond (one prediction every two clock cycles). Software Design and Optimization The software section implements the intraband prediction and the entropy coding modules of the compressor and is coded as an application program under the Linux OS environment. The JPEG-LS median predictor was used for intraband prediction.Besides a ﬁrst-order AAC scheme, the entropy module also per-forms the tasks such as the construction of probability models, probability value updates, coding, and bit stream generation. Various coding optimization techniques were employed to im-prove the execution speed. All ﬂoating point computations were replaced by integer computations. System kernel functions such as “memset” and “memcpy” were used whenever possible to en-hance the efﬁciency of moving large chunk of data between theuser and the kernel spaces. Data layout and the access scheme were carefully planned to improve the cache hit ratio. Compiler optimization options were also turned on to improve thecode quality. To control the hardware acceleration IP, a char-acter type device driver was developed. The interband prediction IP was designed as an AHB slave device and only the processor can initiate data transactions. To minimize the HW/SWcommunication overhead, DMA charged data transfer is usedin lieu of programmed I/O handled by the processor directly via basic R/W operations. The basic unit of each communication is a pixel line to lower the communication frequency. Because ofa relatively simple control ﬂow between the HW/SW sections,a polling scheme is used to synchronize the operations in both sections. IV . S YSTEM IMPLEMENTATION RESULTS AND CONCLUSION Besides the initial proﬁling results, Table I also summarizes the execution times of two implementation versions. In ver-sion 1, the compression algorithm remains unmodiﬁed. The re-sults show that the execution time of the interband prediction module is drastically reduced and the speed up factor is nearly 180 (1436.4 versus 8.0). This means the IP design has suc-cessfully served its acceleration purpose. Relying on codingoptimizations only, the reduction in software execution time is moderate (from 111.2 to 66.4). It turns out that the entire system performance is actually bounded by the software sec-tion design, i.e., the entropy coder. The overall throughput isenhanced from a dismal 0.097 band per second (Bps) to 2.1 Bps, which corresponds to 21 times speed up. In view of this limitation, a simpliﬁed version of entropy coder was adoptedin version two implementation. The execution time is expeditedby 29% at the cost of 0.2–0.3 bpp loss in data compression efﬁciency. The resultant throughput reaches 2.7 Bps. Note that Fig. 7. The baseline version (scheme 1) is a pure software im-plementation without any optimization. The enhancement mea-sures employed incrementally in scheme 2 to scheme 8 are listed as follows: — application program coding optimization (scheme 2);— compiler optimization (scheme 3);— FPGA implementation of initial prediction module (scheme 4); — hierarchical memory access scheme (scheme 5);— FPGA implementation of multi-LUT module (scheme 6);— replacing PIO with DMA transmission (scheme 7); — simpliﬁed AAC coder (scheme 8). Signiﬁcant performance boost was achieved in scheme 4, 5, and6, which correspond to the hardware acceleration by FPGA andthe employment of a smart memory access scheme. In conclusion, a signiﬁcant speed up was achieved in this HW/SW codesign based implementation. Its performance, however, is con-ﬁned by the execution speed of the software section. A purely hardwired design may alleviate this performance barrier but the feasibility depends largely on the algorithm complexity.
