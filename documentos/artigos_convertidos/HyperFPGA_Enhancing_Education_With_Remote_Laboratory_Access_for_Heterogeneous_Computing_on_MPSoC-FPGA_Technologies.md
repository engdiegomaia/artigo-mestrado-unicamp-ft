I NTRODUCTION Technological advancements have transformed education, especially through digital teaching methods such as live broadcasts, interactive platforms, and online courses, which expand access and redefine educator-student interactions [1]–[3]. The Fourth Industrial Revolution has intensified these changes, introducing emerging technologies that enable more personalized, accessible learning experiences. This shift alters not only the used tools but also the pedagogical approaches, moving towards a student-centered model that emphasizes real-time feedback, data-driven assessments, and critical digital skills. Consequently, educators must adapt by developing new competencies and embracing ongoing professional development to effectively integrate these innovations and enhance educational outcomes [4]–[8]. Educational technologies have significantly expanded remote access to resources in different fields, for instance digital electronics [9], [10]. Platforms such as Google Colab, Amazon Web Services, Intel DevCloud, and Microsoft Azure now provide access to CPU, GPU, and FPGA resources for heterogeneous computing [11]–[13]. However, these platforms are limited in that they typically only offer access to one device at a time and impose restrictions on computation time [14]. These platforms enable temporary access to advanced computing for educational courses aimed at promoting technology adoption; however, maintaining long-term access to these remote labs can be prohibitively costly.To address these challenges in courses tailored for developing countries, the Multidisciplinary Laboratory (MLab) within the STI unit at ICTP has developed an experimental cluster of multiprocessor systems-on-chip (MPSoC) based on field-programmable gate array (FPGA) technology [15]. This cluster serves as an experimental platform for scientific computing, incorporating predefined solutions that simplify the use of heterogeneous computing for computational and scientific simulations. In line with ICTP’s mission to disseminate knowledge, we have created a user-friendly environment that enables students to connect remotely and interact directly with the hardware available in workshops organized by our laboratory. This paper introduces a versatile platform that supports both virtual and in-person courses, eliminating the need for instructors to transport equipment or SoC-FPGA prototyping boards. By centralizing hardware resources in a remote laboratory, course logistics are simplified, requiring only a stable internet connection for access. This approach reduces travel and equipment shipping costs while enhancing accessibility, enabling educators to reach a wider audience and offering students from diverse backgrounds a hands-on learning experience. Additionally, the platform encourages collaboration by providing a shared experimental space for innovation, ultimately enriching the educational process. H YPER FPGA CLUSTER This section provides a general overview of the HyperFPGA, detailing the IaC-managed server setup for scalable service provisioning, and the interactive interface and development tools available to students A. Hardware description The HyperFPGA cluster is an experimental system designed for reconfigurable computing. It consists of 16 interconnected nodes arranged in a 2D mesh topology. Figure 1 provides a perspective view of the interconnection between the nodes. Fig. 1. HyperFPGA 2D mesh. Each node includes a Trenz System on Module (SOM) featuring SDRAM, two flash memory chips, a 10-channel programmable phased-locked loop (PLL) clock generator, and several power converters that manage the system’s power sequencing [16]. The core of each SOM is an AMD Zynq UltraScale+ MPSoC EG device, which integrates multiple processing units: •Application Processing Unit (APU): Quad-core Arm Cortex-A53 MPCore operating at up to 1.5 GHz. •Real-Time Processing Unit (RPU): Dual-core Arm Cortex-R5F MPCore, running at up to 600 MHz. •Graphics Processing Unit (GPU): Arm Mali-400 MP2, reaching speeds up to 667 MHz. Additionally, each SOM supports various dynamic memory interfaces, including DDR4, LPDDR4, DDR3, DDR3L, and LPDDR3, along with several high-speed peripherals such as PCIe Gen2, USB 3.0, SATA 3.1, DisplayPort, and Gigabit Ethernet [17].Each SOM is mounted on a square carrier board equipped with a PCI Express connector, USB-UART, JTAG, power distribution circuitry, a Gigabit Ethernet port, and a microUSB connector. Nodes are interconnected through four FX18140P/S-0.8-SH high-density connectors, which are mapped to three distinct types of I/O for FPGA communication: highdensity I/O banks, high-speed I/O banks, and up to four Gigabit transceiver lines. Each carrier board also includes a barrel connector for a 12V external power supply. ARM processors across the cluster communicate via CAT 8 RJ45 cables connected to a 100 Gigabit Ethernet switched network [15]. The nodes run Debian GNU/Linux 12 and include custom drivers for PLL configuration and communication between the microprocessor and FPGA. B. Central server configuration The HyperFPGA server manages the cluster architecture through an IaC approach, leveraging IaC principles to ensure scalability, modularity, and ease of management [18]. In this infrastructure, services and configurations are codified into three main branches: management, user interface, and networking, as shown in Fig. 2, enabling automated provisioning, deployment, and configuration of hardware and virtual environments. This approach is essential for efficiently managing and scaling nodes and users in this experimental cluster, as it reduces manual configuration errors and simplifies updates across multiple nodes. Fig. 2. Service and management configuration of the HyperFPGA Server. The nodes in the HyperFPGA cluster are distributed across a dedicated VLAN, separate from the management and virtual machine VLANs. Each MPSoC-FPGA node is isolated within its own network segment, enhancing secure communication and optimizing network traffic. Key services—such as file sharing, DNS, DHCP, and user authentication—are centrally managed using Ansible [19], which also automates configuration management and service updates across all nodes in the cluster. Virtual machines in this setup can operate as microservices, handling specific tasks that support the cluster’s operation. JupyterHub user environment JupyterHub offers an intuitive and user-friendly interface for users to interact with the cluster, as illustrated in Fig. 3. This platform provides web-based access and manages user sessions, facilitating seamless interaction with the computational resources of the HyperFPGA cluster. Fig. 3. User environment description. The environment includes Python 3 along with various libraries essential for computational tasks, as well as specialized Python libraries for configuring the cluster, interacting with nodes, and distributing computational tasks across the system. Additionally, it provides Python libraries that facilitate the conversion of XSA files generated by Vivado into .bit and .dtbo files, which are necessary for FPGA configuration. The workspace is not designed for users to create and develop digital designs directly on the platform. Instead, it allows users to upload pre-tested designs, developed on their personal computers, to the FPGAs. By offering tools like Vivado, Vitis, and Vitis HLS via a command-line interface, the platform facilitates efficient synthesis and deployment tasks through TCL scripts, ensuring a streamlined and resource-efficient workflow. Users will primarily use Python to manage datatransfer to either their custom accelerators or the predefined ones provided by the platform, simplifying the process and enabling seamless interaction with the hardware. In this context, there are two primary user roles within the environment: •Admin: This role is typically assigned to the course instructor or facilitator, though it can also be performed by the system administrator. The Admin has specific access to directories, such as scratch and bitstreams, which are replicated across all user accounts. These directories allow the Admin to upload files, teaching materials, scripts, or exercises. The Admin can create content within their account for students to interact with, ensuring that students can use the notebooks without modifying them. •Users: In this case, the users are students. They have the ability to create notebooks, organize folders, upload and download files, and access materials shared by the Admin. These users can interact with the provided notebooks and content without altering the original files. Each user environment is equipped with a set of folders and Jupyter Notebooks designed to guide users in learning the basic interaction with the cluster. These resources cover key concepts such as configuration, data transmission, listing the assigned nodes, and displaying the physical location of each node. This helps users understand the data flow, especially if they need to communicate with another node via the FPGA network. As shown in Fig. 4, this is the environment the student interacts with. The overlay includes the implementation of various computation accelerators, complete with data transmission systems for communication between the FPGA and microcontrollers, as well as between FPGAs. III. T HE LEARNING PATH To enhance education with remote laboratory access for heterogeneous computing through the HyperFPGA, the learning path is tailored to the specific course being offered on this platform, with two main tracks: parallel and heterogeneous computing, and the development of accelerators for ad-hoc computing. Each track focus on different aspects of HPC, taking full advantage of the FPGA-based cluster to provide a comprehensive and practical learning experience. Each node includes a generalized communication interface between the processor and FPGA, removing the need for custom Linux drivers and enabling seamless design interaction. Communication with the FPGA’s internal logic is managed via the Python ComBlock library, which provides 16 input and 16 output data registers, input and output FIFOs for serial data transfer, and access to a Dual Port RAM on the FPGA side. This setup allows for specific read and write functions to direct data precisely to the targeted accelerator. Additionally, data can be routed to the processor by simply defining a pool of processors in the Python program, ensuring efficient data transfer and task assignment. For the heterogeneous computing and accelerator track, preconfigured Jupyter templates guide students in understanding FPGA-based accelerators, their performance benefits, and the need for computation acceleration. Students will learn the MPSoC-FPGA architecture and numerical data representation needed to deploy parallel computing on this technology. This includes the use of all cores available per node for parallel computations, and employing distributed computing across multiple nodes. The exercises also introduce IPythonParallel for load balancing, data distribution, and dynamic task management across the FPGA network. In addition to parallel and distributed computing, students can explore key concepts such as data parallelism, task parallelism, and scalability in HPC. The goal is to provide practical experience in designing and optimizing FPGA-accelerated applications, preparing students to solve complex computational problems using modern HPC techniques. The second track focuses on accelerator development for heterogeneous computing, targeting advanced courses in algorithm design using High-Level Synthesis (HLS). This track is aimed at students designing algorithms and digital systems to be implemented on the FPGA. Through remote classes, students can develop both the algorithm and the digital design for their target system. Once synthesized, students upload their bitstream to their user environment, where internal tools facilitate loading it onto the MPSoC-FPGA for interaction via Python notebooks. This process not only demonstrates the practical advantages of FPGA-based acceleration but also enables students to develop custom computational solutions.IV. V. F UTURE WORKS Several enhancements are envisioned to expand the platform’s functionality and flexibility for heterogeneous computing. A primary direction is integrating the GPU within the MPSoC-FPGA, enabling students to leverage its parallel processing capabilities alongside the CPU and FPGA. By incorporating OpenCL for GPU interaction, users will be able to execute complex, multi-device workflows that exploit the strengths of each processing unit (CPU, FPGA, and GPU) in tandem, enriching the learning experience and computational power available for simulations and data-intensive tasks. Another planned enhancement is broadening the programming language support beyond Python. Introducing C and C++ as alternative languages will make the platform more versatile, aligning it with industry standards in HPC and allowing students to choose the language that best suits their application requirements or personal preferences. This will also give them the opportunity to work more closely with lower-level programming, which is crucial for understanding memory management and performance optimization on heterogeneous architectures. Finally, as platform usage grows, migrating service and node management to a Kubernetes-based architecture will be essential for scalability, reliability, and ease of management. Kubernetes will enable dynamic scaling of resources, efficient load balancing, and streamlined deployment of services across multiple nodes. VI. C ONCLUSION This work demonstrates the potential of a custom-designed FPGA-based cluster for advancing education in heterogeneous computing, specifically in resource-constrained contexts. The platform provides accessible, practical learning opportunities in parallel processing and accelerator design for students in scientific and computational fields. By centralizing the hardware and offering remote access, the platform expands accessibility, especially for institutions with limited resources, aligning with ICTP’s mission of knowledge dissemination. The HyperFPGA cluster significantly reduces logistical burdens associated with in-person lab setup, allowing instructors to focus on course content delivery and specific student inquiries. The modular infrastructure and Python-based environment make high-performance computing approachable for a broader audience, enabling students to explore complexconcepts without needing deep expertise in FPGA programming or driver configuration. Moreover, the inclusion of automated tools for FPGA configuration and access to Vivado and Vitis HLS through the platform enriches the educational experience by bridging theoretical learning with hands-on experimentation. The platform fosters collaboration and provides an adaptable environment where students can efficiently explore heterogeneous computing concepts.
